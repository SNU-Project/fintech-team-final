# AI 활용 과정과 검증 내역

## 1. 어디에 어떻게 썼나

| 단계 | AI에게 시킨 일 | 사람이 한 일 |
|---|---|---|
| 프로토타입 | 팀원 5명이 각자 요구사항을 주고 초기 웹앱 생성 | 요구사항 정의, 결과물 취사선택 |
| 통합 | 5개 결과물을 읽고 중복 제거·강점 병합 | 어떤 스택으로 합칠지 결정, 살릴 것/버릴 것 판단 |
| 데이터 | 무료 API 후보 조사, 수집·정제 스크립트 작성 | **CORS 실측**, 산출값이 현실과 맞는지 교차 검증 |
| 검증 | — | 아래 3건의 데이터 조작·오류 적발 |

핵심은 마지막 줄입니다. **AI가 만든 코드는 그럴듯하게 돌아갔지만, 데이터가 가짜였습니다.** 검증 과정에서 잡아낸 것들을 아래에 남깁니다.

## 2. AI 결과물에서 잡아낸 문제

### 2-1. 가짜 과거 성과 곡선 (치명적)

`kihoon/index.html`의 "자산 타임머신"은 과거 투자 성과를 보여준다고 하면서, 실제로는 **사인파로 곡선을 생성**하고 있었습니다.

```js
// 원본 — 실제 가격이 아니라 만들어낸 파형
const buildSeries = (asset, years, index) => {
  const growth = Math.pow(1 + asset.rate, progress * years);
  const wave = 1 + Math.sin(step * 0.82 + index * 1.55) * asset.risk * 0.08 * ...;
  return 100 * growth * wave;
};
```

수익률(`rate`), 변동성(`risk`), 최대낙폭(`drawdown`)도 전부 하드코딩된 상수였습니다. 화면상으로는 진짜 주가 차트처럼 보이는 것이 문제였습니다.

**조치**: 생성기를 통째로 삭제하고 Yahoo Finance 월말 종가 10년치로 재구축했습니다. 지금은 `engine.js`의 `backtest()`가 실제 종가 인덱스를 그대로 사용합니다.

### 2-2. 난수로 만든 백테스트 (치명적)

`nalyang/data_loader.py`는 실제 API(ECOS, FinanceDataReader)를 호출하지만, **실패하면 조용히 난수로 가격을 만들어** 백테스트에 넣고 있었습니다.

```python
# 원본 — API 실패 시 정규분포 난수로 가격 생성
prices = 10000 * np.cumprod(1 + np.random.normal(daily_rate, 0.005, len(dates)))
```

API 키가 없으면 항상 이 경로를 탑니다. 즉 기본 상태에서 화면에 보이던 백테스트 그래프는 전부 난수였습니다.

**조치**: 폴백을 제거했습니다. `pipeline/fetch_data.py`는 수집 실패 시 `DataFetchError`를 던지고 멈춥니다. 값을 지어내느니 화면이 안 뜨는 편이 낫다는 판단입니다.

### 2-3. 잘못된 통계 코드

`nalyang/data_loader.py:114`가 소비자물가지수를 가져온다며 ECOS 통계코드 `721Y001`을 쓰고 있었는데, 이는 시장금리 계열 코드입니다. 소비자물가지수는 `901Y009`입니다.

**조치**: ECOS 대신 **키가 필요 없고 CORS도 열려 있는 OECD SDMX**로 교체했습니다. 결과적으로 API 키 발급 자체가 불필요해졌습니다.

## 3. 우리가 직접 만든 코드에서 잡은 버그

AI에게 맡긴 코드만 문제가 있었던 것은 아닙니다. 통합 과정에서 새로 짠 파이프라인에서도 두 건이 나왔습니다.

### 3-1. 매년 10월 데이터가 사라지던 문제

수집 직후 환율이 121개월 중 111개월만 잡혔습니다. 빠진 달을 나열해 보니 **정확히 매년 10월**이었습니다.

```
결측월: 2016-10, 2017-10, 2018-10, 2019-10, 2020-10, ... 2025-10
```

원인은 시간대였습니다. Yahoo의 월봉 타임스탬프는 거래소 현지시간 기준 월초를 가리키는데, 이를 UTC로 그대로 변환하면 KST 10월 1일 00:00이 UTC 9월 30일 15:00이 되어 **9월 데이터를 덮어썼습니다**. 응답의 `gmtoffset`을 더해 현지 날짜로 되돌려 해결했습니다.

"매년 10월만"이라는 규칙성이 없었다면 그냥 결측치로 넘겼을 문제입니다.

### 3-2. 이상치 필터가 진짜 데이터를 삭제한 문제

원/달러 2017-09에 `0.1154`라는 오류 값이 있었습니다. 이 하나 때문에:

```
S&P 500   변동성 316,029%   최대낙폭 -100%
금        변동성 319,139%   최대낙폭 -100%
비트코인   변동성 460,940%   최대낙폭 -100%
```

처음엔 "중앙값 대비 3배를 벗어나면 제외"로 필터를 짰습니다. 그랬더니 **비트코인의 실제 관측치 50개월이 삭제**됐습니다. 비트코인은 10년간 진짜로 100배 올랐기 때문에, 초기 구간(60만원대)과 최근 구간(1억원대)이 둘 다 중앙값에서 멀어 잘려 나간 것입니다.

오류 틱의 특징은 **크기가 아니라 모양**이라는 점을 놓친 필터였습니다. 들어가는 변화율과 나오는 변화율이 서로 반대 방향으로 극단적인 지점(튀었다가 바로 복귀)만 제거하도록 바꾸자, 제외 대상이 실제 오류 1건으로 정확히 좁혀졌습니다.

### 3-3. 모바일 가로 스크롤

375px에서 페이지 전체에 가로 스크롤이 생겼습니다. 원인은 CSS 그리드의 `1fr`이 사실 `minmax(auto, 1fr)`이고, `auto` 최솟값이 자식의 min-content(숫자 input의 기본 폭 약 400px)라서 컬럼이 컨테이너를 넘어선 것이었습니다. `minmax(0, 1fr)`로 바꿔 해결했습니다.

### 3-4. 보기 좋은 한 날짜가 전체 경험처럼 보이던 문제

자산 타임머신은 사용자가 고른 시작일 하나만 보여 주기 때문에 코로나 급락 직전이나 랠리 직전처럼 특수한 달을 고르면 결과가 과장될 수 있었습니다. 과거 데이터를 만들거나 보간하지 않고, 선택일 **앞뒤 6개월의 실제 관측치만** 다시 계산해 최종금액의 최솟값·중앙값·최댓값을 함께 표시했습니다. 이 값은 `engine.js`의 `backtestWindow()`에서 계산합니다.

### 3-5. 통계 출처가 글자로만 보이던 문제

`data/meta.json`에는 출처 URL이 있었지만 화면은 이름만 출력해 사용자가 원문으로 이동할 수 없었습니다. 모든 출처명을 실제 링크로 바꾸고, 국가데이터처 가계동향조사도 생활 유형 시작값의 근거로 추가했습니다. 링크를 직접 눌러 원문 도메인으로 이동하는 것까지 확인했습니다.

## 4. 검증 방법

만들어진 숫자가 현실과 맞는지 외부 사실로 교차 검증했습니다.

**예: 금, 2021.08 → 2026.08**

| 항목 | 값 |
|---|---|
| 국제 금 시세 (USD) | 약 $1,800 → $4,318 = **+140%** |
| 원/달러 | 1,160원 → 1,420원 = **+22%** |
| 원화 기준 기대 수익률 | 1.40 × 1.22 − 1 ≈ **+193%** |
| **화면 표시값** | **+194.4%** ✅ |

같은 방식으로 KODEX 200(+133%)과 S&P 500(+108%)도 확인했습니다.

또한 `update-data.yml`에 자동 검증을 넣어, 데이터 갱신 때마다 다음 조건을 만족하지 못하면 배포를 막습니다.

- 자산별 관측치 24개월 이상
- CAGR 절댓값 300% 미만
- 연 변동성 500% 미만
- 최대낙폭 −99% 초과 (오류 틱 재발 감지)

## 5. 사용자를 위한 AI 해설 기능

교안의 `프론트엔드 → 서버 API → Gemini` 구조를 실제 서비스에 적용했습니다. 다만 금융 화면에서 AI가 계산까지 맡으면 같은 입력에도 답이 흔들릴 수 있으므로 역할을 분리했습니다.

1. `engine.js`가 실제 물가 데이터와 지출 비중으로 내 물가를 계산합니다.
2. 사용자가 **AI로 쉽게 풀어보기**를 눌렀을 때만 공식 물가·내 물가·차이·최대 영향 품목을 `/api/insight`로 보냅니다.
3. 서버 함수가 입력 범위와 품목 코드를 검증한 뒤 Gemini에 초보자용 해설을 요청합니다.
4. AI가 숫자·수익 보장·종목 추천을 새로 만들면 결과를 폐기하고, 브라우저에서 검증된 기본 해설을 보여 줍니다.

연봉, 월 생활비, 이름, 나이 같은 개인 정보는 보내지 않습니다. API 키(Google AI Studio)는 서버에서만 읽으므로 HTML과 저장소에 키가 들어가지 않습니다. 처음엔 Vercel AI Gateway로 붙였는데 무료 사용량에도 카드 등록을 요구해(2026-08-10, 403의 원인) 카드 없이 쓸 수 있는 Google AI Studio로 교체했습니다. 네트워크나 AI가 실패해도 네 탭의 계산과 시각화는 정상 작동합니다.

이 기능의 목적은 예측이나 추천이 아니라 **이미 검증된 숫자를 처음 보는 사람도 이해할 말로 번역하는 것**입니다.

## 6. 정리

AI로 초기 구현 속도는 크게 올랐지만, **AI가 만든 세 결과물 모두 데이터가 조작되거나 난수였습니다.** 화면만 보고는 알 수 없었고, 데이터 파이프라인을 직접 다시 짜면서 드러났습니다.

이번 프로젝트에서 AI 활용의 실질은 "코드를 얼마나 빨리 생성했나"가 아니라 **"생성된 결과물의 어디를 의심하고 어떻게 확인했나"** 였습니다. 위 5건은 모두 화면상으로는 정상 작동하던 코드에서 나왔습니다.
